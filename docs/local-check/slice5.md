# スライス5（AIアドバイス）ローカル動作確認の手順

## 0. 準備

1. 依存を入れ直す（新しいマイグレーションはないので、DB の作り直しは不要）
   ```bash
   npm install
   ```
2. 自動テストを実行する（AI は偽物を使うので、APIキーは使わない。ローカルの Supabase を起動しておく）
   ```bash
   npm test
   ```
   新しく増えたテスト：`tests/advice.test.ts`（アドバイスを作る流れ、作らない条件、失敗とやり直し、アクセス制御）、`tests/advice-format.test.ts`（本文の形）
3. `.env.local` に次の行があれば、そのままでよい（空なら既定の `gpt-6.1-sol` を使う）
   ```
   OPENAI_ADVICE_MODEL=
   ```
4. `npm run dev` で起動する

## 1. ゲストでアドバイスを確かめる

1. シークレットウィンドウで http://localhost:3000 を開き、コメントの多い動画（質問や要望が多そうなもの。解説・ハウツー系がおすすめ）のURLを入れる
2. 確認すること
   - [ ] 動画を開く前（トップ画面）は、右の枠の「AIアドバイス」に「動画を開くと表示されます」と出る
   - [ ] 分析中は「コメントの分析が終わると、アドバイスを作ります…」と出る
   - [ ] 分析が終わると、再読み込みしなくても、アドバイスが出る（分析の進み具合が100%になってから、数秒〜数十秒かかる）
   - [ ] いちばん上に、全体のまとめ（1〜2文）が太字で出る
   - [ ] その下に「■ 評価された点」「■ 多かった要望・指摘・質問から」「■ 否定的な意見から」「■ 次の動画のアイデア」が出る（項目がないまとまりは出ない）
   - [ ] 「多かった要望・指摘・質問から」が、「〇〇についての声が多かったので（△件）、〜」のように、根拠と提案のセットになっている
   - [ ] 件数が、右の枠のランキングの件数と合っている
   - [ ] 「否定的な意見から」が、責める言い方ではなく、やさしい言い方になっている
   - [ ] 要注意のコメントの言葉や、要注意・スパムの件数が出てこない
   - [ ] 気になる言い方や、物足りない点があれば教えてください（指示文や、モデルを `gpt-6-astra` に変えるかの参考にします）

## 2. コメントが少ない動画

1. ログインして、コメントが10件未満の動画を登録する（再生回数の少ない動画など）
2. 確認すること
   - [ ] 分析が終わると「分析できたコメントが少ないため、アドバイスは作っていません」と出る

## 3. 別の動画に切り替える（ログインユーザー）

1. アドバイスがある動画と、ない動画を、左の一覧で切り替える
   - [ ] 右の枠のアドバイスが、開いた動画のものに変わる（前の動画のアドバイスが残らない）

## 4. スライス4以前に分析した動画（任意）

- [ ] 分析が終わっている古い動画では「この動画のアドバイスはありません」と出る（アドバイスは、新しく分析した動画だけに作られる）

## 5. DB の中身（任意）

Supabase Studio（http://localhost:54323）の SQL Editor で確かめる。

```sql
-- アドバイスの一覧（新しい順）
select v.title, a.advice_summary, a.advice_text, a.model_version, a.triggered_by, a.generated_at
from advice_logs a
join videos v on v.id = a.video_id
order by a.generated_at desc;

-- アドバイスの AI の使用量（トークン数。推定費用は、料金表に gpt-6.1-sol を入れるまで NULL）
select model, input_tokens, output_tokens, estimated_cost_usd, succeeded, duration_ms, created_at
from api_usage_logs
where endpoint = 'advice'
order by created_at desc;
```

- [ ] 1つの動画につき、アドバイスは1行だけ
- [ ] `triggered_by` が `system`、`model_version` が `gpt-6.1-sol`

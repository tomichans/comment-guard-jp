# スライス6 ローカル動作確認の手順

①は利用規約・プライバシーと利用上限（PR #11、確認済み）、②は分類の評価。

# ①利用規約・プライバシー、利用上限

## 0. 準備

1. 依存を入れ直す（新しいマイグレーションはないので、DB の作り直しは不要）
   ```bash
   npm install
   ```
2. 自動テストを実行する（ローカルの Supabase を起動しておく）
   ```bash
   npm test
   ```
   増えたテスト：
   - `tests/register-video.test.ts`：ログインユーザー1人1日10本、アプリ全体1日50本の上限
   - `tests/purge-expired.test.ts`：90日を超えた API使用量の記録が削除されること
   - 手元の画面で1日に50本近く登録した後は、アプリ全体の上限で登録のテストが落ちることがある。そのときは `npm run db:reset`
3. `npm run dev` で起動する

## 1. 利用規約・プライバシーポリシー

1. http://localhost:3000 を開く
2. 確認すること
   - [ ] 左の枠のいちばん下に「利用規約」「プライバシーポリシー」のリンクがある
   - [ ] 左の枠を閉じても、下のアイコン（書類の形）から利用規約を開ける
   - [ ] http://localhost:3000/terms と http://localhost:3000/privacy が、ログインしていなくても開ける
   - [ ] 運営者「tomita」と、連絡先 next.tomita.js@gmail.com が出る（メールのリンクを押すとメールアプリが開く）
   - [ ] 保持期間（24時間、29日、90日）と上限（5本、10本）の数字が正しい
   - [ ] 「アプリに戻る」でメイン画面に戻れる
   - [ ] 登録画面（/signup）に「登録すると、利用規約とプライバシーポリシーに同意したものとみなします」と出て、リンクが開ける
   - [ ] ゲスト（シークレットウィンドウ）のURL入力画面に「『分析する』を押すと、利用規約とプライバシーポリシーに同意したものとみなします」と出る。ログインしているときは出ない
   - [ ] 文章に、事実と違うところや、言い回しを変えたいところがあれば教えてください

## 2. ログインユーザー1人1日10本の上限

本当に10本登録すると AI の費用がかかるので、Supabase Studio で「10本登録した」記録を足して確かめる。

1. ログインして、左下に出るメールアドレスを確認する
2. Supabase Studio（http://127.0.0.1:54323）の SQL Editor で、次を実行する（メールアドレスは自分のものに変える）
   ```sql
   insert into api_usage_logs (service, endpoint, succeeded, user_id)
   select 'youtube', 'videos.list', true, id
   from auth.users, generate_series(1, 10)
   where email = 'あなたのメールアドレス';
   ```
3. 確認すること
   - [ ] 新しい動画のURLを入れると「1日に分析できる動画の数（10本）に達しました。時間をおいて再度お試しください」と出て、登録されない
4. 後片付け（足した記録を消す）
   ```sql
   delete from api_usage_logs
   where user_id = (select id from auth.users where email = 'あなたのメールアドレス')
     and created_at > now() - interval '1 hour';
   ```

## 3. アプリ全体1日50本の上限

1. SQL Editor で、次を実行する（ゲストの記録として50件足す）
   ```sql
   insert into api_usage_logs (service, endpoint, succeeded, guest_id)
   select 'youtube', 'videos.list', true, '00000000-0000-4000-8000-000000000050'
   from generate_series(1, 50);
   ```
2. 確認すること
   - [ ] ログインユーザーで動画を登録しようとすると「アプリ全体の1日の利用上限に達しました。時間をおいて再度お試しください」と出る
   - [ ] シークレットウィンドウ（ゲスト）でも、同じメッセージが出る
3. 後片付け
   ```sql
   delete from api_usage_logs where guest_id = '00000000-0000-4000-8000-000000000050';
   ```

## 4. API使用量の記録の削除（90日）

自動テスト（`tests/purge-expired.test.ts`）で確かめているので、手での確認は不要。
本番では、デプロイのときに登録する1時間ごとのジョブが、動画と一緒に消す。

# ②分類の評価

## 5. 正解を確認する（いちばん大事）

`eval/classification-dataset.json` の100件は、Claude が作った架空のコメントと、正解の案です。
正解は、このアプリの基準（要件定義書9.1：少しでも悪意やきつい言い方があれば要注意）で付けています。

1. ファイルを開き、各コメントの `expected`（正解）が、海斗さんの感覚と合っているかを見る
   - `harmful` 要注意、`spam` スパム、`feedback` 指摘・要望、`question` 質問、`praise` ポジティブ、`negative_opinion` 否定的意見、`other` その他
   - `note` は、そのコメントで何を試したいかのメモ（境界の例など）
2. 違うと思うものは、`expected` を書き換えるか、IDを教えてください
   - 特に、要注意（h01〜h20）と否定的意見（n01〜n12）の境目、その他（o01〜o15）と質問・ポジティブの境目
3. 足したいコメント（実際に見かけて困った言い方など）があれば、同じ形で足してかまいません（IDは重ならないように）

## 6. 評価を実行する

1. ローカルの Supabase を起動しておく（NGワードを DB から読むため）
2. `.env.local` に `OPENAI_API_KEY` があることを確かめる
3. 実行する（1〜2分。費用は数円の見込み）
   ```bash
   npm run eval
   ```
4. 確認すること
   - [ ] 最後に「[eval] 正解率 ◯%、要注意の見逃し ◯件。docs/evaluation.md に書き出しました」と出る
   - [ ] `docs/evaluation.md` に、まとめ・分類ごとの結果・混同行列・正解と違ったコメントの表がある
   - [ ] 「正解と違ったコメント」を見て、AI が間違っているのか、正解のほうを直すべきかを考える（正解を直したら、もう一度実行する）
5. 結果（`docs/evaluation.md`）の数字を教えてください。正解率と見逃しの件数を見て、分類の指示文を直すかを相談します
6. 自動テストも通ることを確かめる（集計の計算のテスト `tests/eval-metrics.test.ts` が増えた）
   ```bash
   npm test
   ```

AI の結果は毎回少し変わるので、2〜3回実行して、数字が大きく変わらないかも見ておくと安心です。

# ③README

## 7. README を読む

GitHub の PR の「Files changed」で README を開くと、表と図（mermaid）が表示された状態で読めます。
採用担当の目で、次の点を見てください。

- 「何を解決するアプリか」「設計で工夫したこと」が、自分の言葉で説明できる内容になっているか（面接で聞かれる想定で）
- 事実と違うところ、言い過ぎのところがないか

## 8. スクリーンショットを撮って入れる

1. `npm run dev` で起動し、料理動画などを1本登録して、分析が終わるまで待つ
2. 画面幅1440px くらいで、コメント一覧・ランキング・AIアドバイスが見える状態を撮る
   - 投稿者名が写る場合は、ぼかすか、写らない位置で撮る（他人の名前を公開しないため）
   - 攻撃的なコメントが写らないよう、「ポジティブ」タブで撮るのがおすすめ
3. `docs/images/main.png` として保存する
4. README の `<!-- スクリーンショット … -->` のコメントを外して、画像の行だけを残す
5. PR のブランチにコミットして push する

# セキュリティ対策の動作確認（ローカル）

この PR で足した「セキュリティ用のヘッダー」と「パスワード8文字以上」を、ローカルで確かめる手順です。

## 準備

```bash
npx supabase stop
npx supabase start   # config.toml の minimum_password_length = 8 を反映するため、起動し直す
npm run dev
```

## 1. セキュリティ用のヘッダー

別のターミナルで、次を実行します。

```bash
curl -sI http://localhost:3000/ | grep -iE "content-security-policy|x-frame-options|x-content-type-options|referrer-policy|permissions-policy|strict-transport-security|x-powered-by"
```

- [ ] 次の6行が出る
  - `Content-Security-Policy: frame-ancestors 'none'; object-src 'none'; base-uri 'self'; form-action 'self'`
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains`
- [ ] `X-Powered-By` の行は出ない
- [ ] 画面を一通り操作して（ゲストで分析、ログイン、ログアウト、動画の削除）、今までどおり動く

## 2. パスワード8文字以上

`http://localhost:3000/signup` を開きます。

- [ ] パスワード欄の下に「8文字以上で入力してください」と出る
- [ ] 7文字で「登録する」を押すと、ブラウザが止める（送信されない）
- [ ] 8文字で登録できる
- [ ] ログイン画面（`/login`）には、文字数の案内は出ない（登録済みのパスワードを、そのまま確かめるため）

- [ ] README の「6. セキュリティと個人情報の扱い」を読み、内容に違和感がない
